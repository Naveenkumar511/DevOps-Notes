1. WHAT IS VIRTUALIZATION?
==================================================

Virtualization is the technology that allows multiple virtual machines (VMs) to run on a single physical server.

Before Virtualization:
--------------------------------------------------
1 Physical Server = 1 Operating System
= Low resource utilization
= High hardware cost

After Virtualization:
--------------------------------------------------
1 Physical Server
   |
   |---- VM1 (Linux)
   |---- VM2 (Windows)
   |---- VM3 (Ubuntu)

= Better resource utilization
= Reduced cost
= Easy management

--------------------------------------------------

How Virtualization Works?

A software called Hypervisor sits between the hardware and virtual machines.

Physical Server
       |
   Hypervisor
       |
   VM1  VM2  VM3

--------------------------------------------------

Examples of Hypervisors

- VMware ESXi
- Microsoft Hyper-V
- Xen

--------------------------------------------------

5. Isolation between VMs
6. Scalability

Elastic Load Balancer:
================

	An Elastic Load Balancer (ELB) is a service used to distribute incoming network traffic across multiple servers or instances to ensure high availability and reliability. 


Types of Elastic Load Balancers (in AWS):
--------------------------------------------------

1.Application Load Balancer (ALB)

	Works at Layer 7 (Application Layer) of the OSI model.

	Routes traffic based on content rules (e.g., URL path, hostname).

	Best for web applications and microservices.

2.Network Load Balancer (NLB)

	Works at Layer 4 (Transport Layer).

	Handles TCP, UDP, and TLS traffic.

	Designed for high-performance, low-latency applications.

3.Gateway Load Balancer (GLB)

	Specialized for third-party virtual appliances.

	Useful for security appliances like firewalls or intrusion detection systems.

4.Classic Load Balancer (CLB) [Legacy]

	Operates at both Layer 4 and Layer 7.

	Older service, now mostly replaced by ALB and NLB.




ELB Deployment Models:
------------------------------
1.Internet-facing ELB:

	Handles traffic from the public internet.

	Commonly used for web applications (e.g., websites, APIs).

	Example: AWS Elastic Load Balancer with public IPs.

2.Internal ELB (Private)

	Routes traffic within a private network.

	Used for internal services or microservices communication.

	Example: Internal Azure Load Balancer (ILB) for VM-to-VM traffic distribution.


1. Health Check:

	A Health Check is a mechanism used by the load balancer to monitor the status of backend servers. It ensures that only healthy servers receive traffic.

2. Target Group:
	
	A Target Group is a logical collection of backend servers that the load balancer routes traffic to.

3. Listener:

	A Listener is a process that checks for connection requests from clients on a specific port and protocol.

	It defines how the load balancer receives incoming traffic.

	Listeners use rules to determine how to forward requests to target groups.

4. Rules
	
	Rules define how the load balancer routes incoming traffic to specific target groups based on conditions.

Sticky sessions:

	Sticky sessions route requests to the same target in a target group. You enable sticky 
sessions at the target group level. You can also set the duration for the stickiness of 
the load balancer-generated cookie, in seconds. Useful if you have stateful 
applications. 


Load Balancer States: 
--------------------------
	Provisioning – The load balancer is being set up. 
	Active – The load balancer is fully set up and ready to route traffic. 
	Failed – The load balancer could not be set up.

Auto Scaling in AWS:
================ 
	Auto Scaling in AWS is a service that automatically adjusts the number of EC2 instances (or other resources) based on demand or predefined conditions. It helps you:

	Scale out → Add more instances when demand increases.

	Scale in → Remove instances when demand decreases.

	Maintain availability → Keep a specified number of healthy instances running at all times.

	Optimize costs → Only pay for the resources you actually need.



Auto Scaling Group (ASG):
--------------------------------
	An Auto Scaling Group (ASG) is a collection of EC2 instances managed together. It defines:

		Minimum capacity: The minimum number of instances to keep running.

		Maximum capacity: The maximum number of instances allowed.

		Desired capacity: The target number of instances under normal conditions.

What is a Launch Template in AWS?:
--------------------------------------------
	A Launch Template in AWS is a blueprint for launching EC2 instances. It defines the configuration settings required to create new instances, including:

		1.The AMI ID (Amazon Machine Image)

		2.The instance type (e.g., t2.micro, m5.large)

		3.Key pair for SSH/RDP access

		4.Security groups and network settings

		5.IAM role permissions

		6.User data scripts (for initialization tasks)

Amazon EBS (Elastic Block Store):
=========================
	Amazon EBS is a scalable, high-performance block storage service used with Amazon EC2 instances. It provides persistent storage that retains data even when the EC2 instance is stopped or terminated.

Key Features of EBS:
-------------------------
	1.Persistent Storage: Data on EBS volumes persists independently of the EC2 instance lifecycle.

	2.Scalability: You can increase volume size, adjust performance, or change volume types without downtime.

	3.Snapshots: You can create incremental snapshots of EBS volumes, which are stored in Amazon S3.

	4.Encryption: EBS volumes support encryption at rest using AWS Key Management Service (KMS).

	5.Backup & Restore: You can restore an EBS volume from a snapshot to recover data.



EBS Volume Types:
-----------------------
EBS offers multiple volume types optimized for performance and cost.

SSD-backed volume
HDD-backed volume

IOPS - Input Output Operation per Second

1.gp3 (General Purpose SSD)
	
2.gp2 (General Purpose SSD)	
	
3.io1/io2 (Provisioned IOPS SSD)	
	
4.st1 (Throughput Optimized HDD)	
	
5.sc1 (Cold HDD)	
	

What is an EBS Snapshot?
-------------------------------
	An EBS Snapshot is a point-in-time backup of your EBS volume, stored in Amazon S3. It captures the entire volume's data at a specific moment, allowing you to restore it later or create new volumes from it.

Key Features of EBS Snapshots:
--------------------------------------
	1.Incremental Backups:

		After the first full backup, only changed data blocks are saved in subsequent snapshots, making them cost-efficient.

	2.Stored in S3:

		Snapshots are stored in Amazon S3, but you won’t see them directly in S3—it’s managed by AWS.

	3.Cross-Region and Cross-AZ Replication:

		You can copy snapshots to other regions for disaster recovery or backup purposes.

	4.Fast Restore:

		You can restore from a snapshot to create a new EBS volume.

How to Attach an Amazon EBS Volume to Multiple EC2 Instances:
--------------------------------------------------------------------------------

	By default, Amazon EBS volumes are designed to be attached to only one EC2 instance at a time. However, AWS offers multi-attach support for io1/io2 volumes, allowing up to 16 instances to access the same volume simultaneously.

Requirements for Multi-Attach:
---------------------------------------
 	1. Volume Type: Only io1 and io2 volumes support multi-attach.
 	2. Instances in the Same AZ: All EC2 instances must be in the same Availability Zone (AZ).
 	3. File System Compatibility: Use a cluster-aware file system (e.g., Lustre, Oracle ASM, or GPFS) to prevent data corruption.
 	4. Supported Instance Types: Only Nitro-based instances (e.g., m5, c5, r5) support multi-attach.

Amazon EFS ( Elastic File System )
========================

	Amazon EFS is a fully managed, scalable file storage service offered by AWS. It provides a shared, elastic, and distributed file system that you can mount across multiple EC2 instances (or containers and Lambda functions) simultaneously. It supports the NFS (Network File System) protocol, making it ideal for Linux-based workloads.

Key Features of EFS:
--------------------------

	Elastic and Scalable:

		Automatically grows and shrinks as you add or remove files.

		No need to provision storage capacity upfront.

	Shared Access:
	
		Multiple EC2 instances can access the same file system concurrently.

		Ideal for distributed applications, web servers, and content management.

	Fully Managed:

		AWS handles infrastructure, capacity, and maintenance.

		You just create and mount the file system.

	Performance Modes:

		General Purpose: Best for latency-sensitive workloads.

		Max I/O: Optimized for high-throughput applications (e.g., big data, media processing).

	Security:

		Supports IAM policies, VPC access, and encryption.



Common Use Cases for EFS
-----------------------------------

	Web applications: Shared storage for multiple web servers (e.g., Apache, NGINX).

	Content management systems (CMS): Centralized file repository.

	Data analytics: Shared access for big data processing.

	Container storage: Persistent storage for ECS/EKS.

	Backup and recovery: Centralized file backup.

Amazon S3 (Simple Storage Service)
==========================
	Amazon S3 is a scalable, durable, and secure object storage service offered by AWS. It allows you to store and retrieve any amount of data, at any time, from anywhere on the web. S3 is widely used for data lakes, backups, content distribution, and static website hosting.

Key Features of S3
-----------------------

1. Object Storage:

	S3 stores data as objects inside buckets.

2. Each object consists of:

	Data (the actual content you upload).

3. Metadata (key-value pairs with descriptive info).

	Unique Key (the filename or identifier).

4. Unlimited Storage:

	No limit on the number of objects or total storage capacity.

	Individual objects can be up to 5 TB in size.

5. Versioning & Lifecycle Policies:

	Supports versioning to keep multiple versions of an object.

	Lifecycle policies automate transitioning data to cheaper storage classes.

6. Durability & Availability:

	99.999999999% (11 nines) durability.

	99.99% availability.

7. Security & Compliance:

	Supports encryption (both server-side and client-side).

	IAM policies and Bucket policies control access.

	Compliant with HIPAA, PCI-DSS, ISO, and more.


Storage Classes:
---------------------
	S3 Standard: For frequently accessed data.
	
	S3 Standard-IA (Infrequent Access): Lower-cost storage for less frequently accessed data.

	S3 One Zone-IA: Cheaper, but stores data in a single AZ (Availability Zone).

	S3 Intelligent-Tiering: Automatically moves objects between frequent and infrequent access tiers.

	S3 Glacier ( Instant / Flexible retrieval) : Low-cost archival storage (retrieval in minutes to hours).

	S3 Glacier Deep Archive: Cheapest option for long-term storage (retrieval in hours).
	
	S3 Express one zone 


Common Use Cases for S3:
----------------------------------
	Data lakes & analytics: Store and process massive datasets.

	Backup & recovery: Reliable storage for backups.

	Static website hosting: Host HTML/CSS/JS websites directly from S3.

	Content distribution: Store images, videos, and files for CDNs.

	Data archiving: Use S3 Glacier for low-cost, long-term archiving.



Amazon S3 Replication
================
	Amazon S3 Replication is a feature that automatically copies objects from one S3 bucket to another. It can replicate data within the same AWS region (SRR) or across different regions (CRR), making it useful for backup, disaster recovery, and data distribution.

Types of S3 Replication
-------------------------------

1.Same-Region Replication (SRR)

	Replicates objects within the same AWS region.

	Use cases:

		Compliance: Maintain multiple copies of data in the same region.

		Log aggregation: Consolidate logs into a single bucket.

2.Cross-Region Replication (CRR)

	Replicates objects to a different AWS region.

	Use cases:

		Disaster recovery: Store a copy in a geographically separate region.

		Latency optimization: Serve content closer to users in another region.

		Compliance: Meet regulatory requirements by keeping copies in multiple regions.

AWS Storage Gateway
================


AWS Storage Gateway is a hybrid cloud storage service that connects your on-premises environments (like data centers or branch offices) to AWS Cloud Storage. It allows organizations to seamlessly use AWS storage services such as Amazon S3, Amazon Glacier, and Amazon EBS without fully migrating everything to the cloud immediately.

Type: Hybrid Storage (on-premises to cloud)

Use Cases: Backup, disaster recovery, data migration

Key Features:

File Gateway: Access S3 as a file share

Volume Gateway: Block storage with cloud backups

Tape Gateway: Replace physical tape infrastructure

AWS IAM (Identity and Access Management)

===============================

1. WHAT IS IAM?
===============================

IAM (Identity and Access Management) is a Global AWS service used to securely control access to AWS resources.

It helps answer three questions:

• Who can access AWS?
• What actions can they perform?
• Which AWS resources can they access?

IAM allows you to create users, groups, roles, and policies to manage permissions.

Example:
A company has Developers, DevOps Engineers, and Administrators. Each team requires different levels of access. IAM helps provide the correct permissions to each team.

Important:
IAM is a Global Service. Once created, IAM users and roles are available across all AWS Regions.

--------------------------------------------------

2. WHY DO WE NEED IAM?
===============================

Without IAM:
• Everyone would use the AWS Root Account.
• No control over permissions.
• High security risk.
• Difficult to track user activities.

With IAM:
• Individual user accounts can be created.
• Permissions can be controlled.
• User activities can be audited.
• Security is improved.

Example:
A developer only needs access to EC2.
An administrator needs full AWS access.
IAM allows both users to have different permissions.

--------------------------------------------------

3. FEATURES OF IAM
===============================

• Centralized access management.
• Fine-grained permissions.
• Multi-Factor Authentication (MFA).
• Temporary security credentials.
• Integration with AWS services.
• Supports federation with external identity providers.
• Password policies.
• Access Analyzer.
• Credential reports.

--------------------------------------------------

4. IAM COMPONENTS
===============================

IAM consists of four major components:

1. Users
2. Groups
3. Policies
4. Roles

--------------------------------------------------

4.1 IAM USERS
===============================

IAM User represents an individual person or application that requires AWS access.

Examples:

Users can access AWS using:

1. AWS Management Console

--------------------------------------------------

Important Points:

--------------------------------------------------

4.3 IAM POLICIES
===============================

Policies define permissions.

Policies are JSON documents that determine what actions are allowed or denied.

Policy answers:

• What action?
• On which resource?
• Allow or deny?

Basic Policy Structure:

{
    "Version":"2012-10-17",
    "Statement":[
        {
            "Effect":"Allow",
            "Action":"",
            "Resource":""
        }
    ]
}

Policy Elements:

Version:
Specifies policy language version.

Effect:
• Allow
• Deny

Action:
Defines operations.

Examples:
• s3:GetObject
• ec2:StartInstances
• ec2:StopInstances

Resource:
Defines AWS resources.

Example:
arn:aws:s3:::mybucket/*

--------------------------------------------------

4.4 IAM ROLES
===============================

IAM Roles provide temporary permissions.

Roles do NOT have:

• Passwords
• Access Keys

Roles are assumed when needed.

Workflow:

User/Application
       ↓
Assume Role
       ↓
Temporary Credentials
       ↓
Access AWS Resources

Advantages:
• More secure.
• No long-term credentials.
• Easy cross-service access.

--------------------------------------------------

5. TYPES OF IAM POLICIES
===============================

5.1 AWS MANAGED POLICIES

Created and maintained by AWS.

Examples:
• AdministratorAccess
• AmazonS3ReadOnlyAccess
• AmazonEC2ReadOnlyAccess

Advantages:
• Ready to use.
• Automatically updated.

Disadvantages:
• May provide excessive permissions.

--------------------------------------------------

5.2 CUSTOMER MANAGED POLICIES

Created by customers.

Advantages:
• Fully customizable.
• Reusable.

Example:
Allow only:
• EC2 Start

--------------------------------------------------

5.3 INLINE POLICIES

Policies embedded directly into users, groups, or roles.

Characteristics:
• One-to-one relationship.
• Cannot be reused.
• Deleted along with the identity.

Use Case:
Special permissions for a single user.

VPC (Virtual Private Cloud):
=====================

	A VPC (Virtual Private Cloud) in AWS (Amazon Web Services) is a logically isolated network within the AWS cloud where you can launch and manage AWS resources. It allows you to define your own network configuration, including IP address ranges, subnets, route tables, and security settings.

Key Features of AWS VPC:
--------------------------------
1. Private and Public Subnets 
	You can create subnets within a VPC, some with internet access (public) and some without (private).

2. Security Controls 
	Use Security Groups (firewall rules for instances) and Network ACLs (firewall rules for subnets).

3. Custom IP Addressing  
	Define your own IP range using CIDR (Classless Inter-Domain Routing).

4. Internet Gateway (IGW)  
	Allows public access to resources in a public subnet.

5. NAT Gateway 
	Enables instances in private subnets to access the internet securely.

6. VPC Peering  
	Connects two VPCs to allow communication between them.

7. VPC Endpoints  
	Connects your VPC privately to AWS services without using the internet.

Subnet:
---------
	A Subnet in AWS is a segment of a VPC’s IP address range that allows you to organize and control network traffic within your Amazon Virtual Private Cloud (VPC). Each subnet is confined to a single Availability Zone (AZ) and can be categorized as either public or private, depending on its route table configuration.


Route Table:
---------------
	A Route Table in AWS is a set of rules (routes) that determine how network traffic is directed within a VPC (Virtual Private Cloud). Every subnet in a VPC must be associated with a route table, which controls where outgoing traffic is sent.


Internet Gateway (IGW):
------------------------------
	An Internet Gateway (IGW) in AWS is a highly available and scalable component that allows instances in a public subnet within an Amazon VPC (Virtual Private Cloud) to access the internet and receive inbound traffic. It serves as a bridge between the AWS network and the external internet.


NAT Gateway:
-----------------
	A NAT Gateway (Network Address Translation Gateway) in AWS allows instances in a private subnet to initiate outbound internet traffic while preventing inbound connections from the internet.


Elastic IP (EIP):
-------------------
	An Elastic IP (EIP) in AWS is a static, public IPv4 address that you can allocate to your AWS account and assign to resources, such as EC2 instances, NAT Gateways, or Load Balancers. It allows you to maintain a consistent public IP address even if you stop, restart, or replace an instance.

=====================================================================================

VPC peering:
=========
	VPC peering (Virtual Private Cloud peering) is a networking connection that allows you to route traffic privately between two VPCs (Virtual Private Clouds), as if they were on the same network.

Key Points:
--------------
	1. Private communication: Traffic between peered VPCs stays within the cloud provider’s backbone network (no public internet involved).

	2. Cross-account or same account: You can peer VPCs within the same account or between different accounts.

	3. One-to-one relationship: Each VPC peering connection is between two VPCs. If VPC A is peered with B, and B is peered with C, A is not automatically peered with C (no transitive peering).

	4. Low latency and high throughput: Useful for workloads that require fast, secure, and private communication between VPCs.

Common Use Cases:
-------------------------
Microservices in separate VPCs

Shared services (like centralized logging or authentication)

Merging environments (e.g., development and production VPCs)

Transit Gateway:
============
	A Transit Gateway is a cloud networking service that acts as a central hub to connect multiple VPCs and on-premises networks through a single gateway.

	Think of it like a hub-and-spoke model, where the Transit Gateway is the hub, and VPCs or VPN connections are the spokes.

Key Features:
----------------
	Scalable: Connect hundreds of VPCs without creating complex peering meshes.

	Centralized routing: Manage all routing rules from a single point instead of updating each VPC individually.

	Supports VPN and Direct Connect: You can hook up your on-premises network via site-to-site VPN or AWS Direct Connect.

	No transitive peering limitation: Unlike VPC peering, it allows transitive routing—e.g., VPC A can talk to VPC C via the Transit Gateway, even if they aren't directly connected.

What is Amazon RDS?
================
	Amazon RDS is a managed relational database service that helps developers and DBAs deploy and operate relational databases in the cloud without having to manage the underlying infrastructure (e.g., hardware, OS, database software, backups, etc.).

	It’s part of AWS’s PaaS (Platform-as-a-Service) offerings.

Why Use RDS?
-----------------

	Traditionally, setting up a database involves:

	Installing and configuring the database software

	Patching and updating

	Setting up backups

	Ensuring high availability

	Scaling with demand

	RDS handles all of this for you, so you can focus on using the database, not managing it.

Supported Database Engines:
------------------------------------

Amazon Aurora		AWS-optimized, super fast, MySQL & PostgreSQL compatible
MySQL				Popular open-source option
PostgreSQL			Advanced open-source DB with strong features
MariaDB				MySQL fork, also open source
Oracle				Enterprise-grade, requires license
SQL Server			From Microsoft, great for Windows-heavy shops
IBM DB2

Key Features:
-----------------

1. Provisioning and Configuration
	Pick your DB engine, version, and instance size.

	Select storage (SSD-backed: General Purpose (gp3), Provisioned IOPS).

	Choose your VPC/subnet for networking.

2. Backups
	Automated backups: Daily backups + transaction logs (point-in-time recovery up to 35 days).

	Manual snapshots: You can create and keep these as long as you want.

3. High Availability with Multi-AZ
	Automatically replicates your DB to a standby instance in another AZ (Availability Zone).

	In case of failure, RDS fails over automatically.

	Multi-AZ is for HA (High Availability), not scaling reads.

4. Read Replicas
	Replicate data asynchronously to other RDS instances.

	Useful for read-heavy apps (e.g., analytics, reporting).

	Can also promote a read replica to become the master (manual failover).

5. Monitoring & Security
	Amazon CloudWatch for metrics (CPU, memory, storage).

	Enhanced Monitoring for OS-level metrics.

	IAM integration for access control.

	Encryption using KMS (for storage, backups, and snapshots).

	Supports VPC (private networking) and security groups (firewall rules).

6. Maintenance
	AWS applies patches/upgrades during your defined maintenance window.

	Minor version updates are automatic; major version upgrades are optional.

CloudWatch:
==========
	CloudWatch is a monitoring and observability service provided by Amazon Web Services (AWS). It's used to collect and track metrics, collect and monitor log files, set alarms, and automatically respond to changes in your AWS environment.

Key Features:
-----------------
1. Metrics Monitoring

	Tracks metrics like CPU usage, memory, disk I/O, network traffic, etc., from AWS resources like EC2, RDS, Lambda, and more.

2. Log Monitoring (CloudWatch Logs)

	Collects and stores logs from AWS services and applications. You can search, filter, and analyze logs in near real-time.

3. Alarms

	Set thresholds on metrics and trigger alarms if they're crossed (e.g., send notification if CPU usage > 80%).

4. Dashboards

	Custom dashboards to visualize data from multiple AWS resources in one place.

5. Events (CloudWatch Events / EventBridge)

	Respond to events (e.g., a change in an EC2 state) and trigger actions like starting a Lambda function or sending a message.

6. CloudWatch Agent

	Can be installed on servers (even outside AWS) to push custom metrics and logs to CloudWatch.

Use Cases:
-------------
	Monitoring performance and resource utilization

	Troubleshooting issues using logs

	Automating responses to incidents

	Setting up alerts for system health

	Creating operational dashboards

	
CloudWatch Alarm:
------------------------
	A CloudWatch Alarm in AWS is a tool that helps you automatically monitor AWS resources and applications by watching a specific metric or a mathematical expression of multiple metrics, and triggering actions when a specified threshold is breached.

What It Does:
----------------
	A CloudWatch Alarm continuously monitors a metric, and when that metric crosses a threshold you set (either above or below), it performs an action like:

		Sending a notification (via Amazon SNS)

		Auto-scaling an EC2 instance

		Restarting, stopping, or terminating an EC2 instance

		Executing an AWS Systems Manager Automation runbook

CloudTrail:
========

	AWS CloudTrail is a service that helps you track user activity and API usage across your AWS environment. It’s basically like a security camera for your AWS account—it records who did what, when, and from where.

What CloudTrail Does:
---------------------------
Records every API call made in your account (including from AWS Management Console, SDKs, CLI, and other AWS services).

Captures event history of your AWS account activity, including:

	Who made the request (IAM user/role/service)

	When it happened

	What resources were affected

	Source IP address

	Whether the action was successful

Why It’s Useful:
-------------------
	Security & Compliance – Detect suspicious activity and meet auditing requirements.

	Operational Troubleshooting – See what changes were made before something broke.

	Governance – Understand usage patterns and access behavior.

Where It Stores Data:
--------------------------
You can set CloudTrail to deliver logs to S3 buckets, and optionally to CloudWatch Logs or EventBridge for alerting and automation.

Lambda:
======

	AWS Lambda is a serverless compute service that lets you run code without provisioning or managing servers. You just upload your code, set a trigger, and AWS takes care of everything else—scaling, running, and maintaining the infrastructure.

In Simple Terms:
--------------------
Lambda is like saying: “Here’s my code. Run it when this thing happens.”

Key Features:
----------------
	No servers to manage – AWS handles everything

	Auto-scaling – Runs your code in parallel in response to triggers

	Pay-per-use – You only pay for the compute time your code actually uses (down to the millisecond)

	Supports multiple languages – Python, Node.js, Java, Go, .NET, Ruby, etc.

Common Triggers:
----------------------
	API Gateway – Run a function when an HTTP request is made

	S3 – Run a function when a file is uploaded

	DynamoDB Streams – React to changes in your NoSQL database

	CloudWatch Events – Run on a schedule or in response to AWS events

	SNS/SQS – Process messages from topics or queues

Example Use Case:
-----------------------
	Let’s say you upload a photo to an S3 bucket:

		An S3 event triggers a Lambda function

		Lambda resizes the image and stores it in another bucket

		You didn’t have to create or manage any servers to make that happen 

Anatomy of a Lambda:
---------------------------
	Handler Function – Your main code entry point

	Event Object – Contains the data that triggered the function

	Context Object – Info about the execution environment (timeouts, request ID, etc.)
