# 1. Introduction

Modern applications run on multiple servers, containers, and Kubernetes clusters.

If one server crashes or CPU usage becomes very high, users may experience slow responses or downtime.

Monitoring helps DevOps engineers detect issues before users are affected.

---

# 2. What is Monitoring?

Monitoring is the continuous process of collecting system and application metrics to understand the health and performance of your infrastructure.

It helps answer questions like:

- Is the server running?
- Is CPU usage too high?
- Is memory running out?
- Is disk space full?
- Is the application responding?

### Real-World Example

Imagine driving a car.

The dashboard continuously displays:

- Speed
- Fuel Level
- Engine Temperature

These values help you identify problems before the car stops.

Monitoring works the same way for servers.

---

# Why Monitoring?

Without monitoring:

- Unexpected server crashes
- Slow websites
- Disk full errors
- High CPU usage
- Users report problems first

With monitoring:

- Detect issues early
- Receive alerts automatically
- Improve application performance
- Reduce downtime

---

# 3. Monitoring vs Observability

## Monitoring

Monitoring tells you:

> "What is happening?"

Example:

- CPU Usage = 95%
- Memory Usage = 90%

Monitoring detects the problem.

---

## Observability

Observability tells you:

> "Why did it happen?"

Example:

User Request

↓

Application

↓

Database Slow

↓

API Timeout

↓

CPU Spike

Observability helps identify the root cause.

---

# Monitoring vs Observability

| Monitoring | Observability |
|------------|---------------|
| Detects problems | Explains problems |
| Uses metrics | Uses metrics, logs, traces |
| Shows alerts | Finds root cause |

---

# 7. What is Prometheus?

Prometheus is an open-source monitoring and alerting system.

Originally developed by SoundCloud.

Now maintained by the Cloud Native Computing Foundation (CNCF).

Prometheus collects metrics from servers and applications and stores them in a Time Series Database.

# 1. Installing Prometheus (Ubuntu 22.04)

## Step 1: Update the Server

```bash
sudo apt update
sudo apt upgrade -y
```

---

## Step 2: Create Prometheus User

```bash
sudo useradd --no-create-home --shell /bin/false prometheus
```

Verify

```bash
id prometheus
```

---

## Step 3: Create Required Directories

```bash
sudo mkdir /etc/prometheus
sudo mkdir /var/lib/prometheus
```

Assign ownership

```bash
sudo chown prometheus:prometheus /etc/prometheus
sudo chown prometheus:prometheus /var/lib/prometheus
```

---

## Step 4: Download Prometheus

```bash
cd /tmp

wget https://github.com/prometheus/prometheus/releases/latest/download/prometheus-*.linux-amd64.tar.gz
```

Extract

```bash
tar -xvf prometheus-*.tar.gz
```

Go inside the folder

```bash
cd prometheus-*
```

---

## Step 5: Copy Files

Binary files

```bash
sudo cp prometheus /usr/local/bin/
sudo cp promtool /usr/local/bin/
```

Configuration

```bash
sudo cp prometheus.yml /etc/prometheus/
```

Console files

```bash
sudo cp -r consoles /etc/prometheus
sudo cp -r console_libraries /etc/prometheus
```

Set ownership

```bash
sudo chown -R prometheus:prometheus /etc/prometheus
sudo chown prometheus:prometheus /usr/local/bin/prometheus
sudo chown prometheus:prometheus /usr/local/bin/promtool
```

---

# 2. Create Prometheus Service

Create service file

```bash
sudo nano /etc/systemd/system/prometheus.service
```

Paste

```ini
[Unit]
Description=Prometheus
After=network.target

[Service]
User=prometheus
Group=prometheus

ExecStart=/usr/local/bin/prometheus \
--config.file=/etc/prometheus/prometheus.yml \
--storage.tsdb.path=/var/lib/prometheus

Restart=always

[Install]
WantedBy=multi-user.target
```

---

Reload systemd

```bash
sudo systemctl daemon-reload
```

Enable service

```bash
sudo systemctl enable prometheus
```

Start service

```bash
sudo systemctl start prometheus
```

Check status

```bash
sudo systemctl status prometheus
```

---

Default Port

```
9090
```

Open in browser

```
http://SERVER-IP:9090
```

# 7. Top 20 PromQL Queries

## 1. CPU Idle

```promql
node_cpu_seconds_total{mode="idle"}
```

---

## 2. CPU Usage %

```promql
100 - (avg by(instance)(rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
```

---

## 3. Total Memory

```promql
node_memory_MemTotal_bytes
```

---

## 4. Available Memory

```promql
node_memory_MemAvailable_bytes
```

---

## 5. Used Memory

```promql
node_memory_MemTotal_bytes - node_memory_MemAvailable_bytes
```

---

## 6. Memory Usage %

```promql
100 * (1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes))
```

---

## 7. Disk Size

```promql
node_filesystem_size_bytes
```

---

## 8. Free Disk

```promql
node_filesystem_avail_bytes
```

---

## 9. Disk Usage %

```promql
100 - (
node_filesystem_avail_bytes
/
node_filesystem_size_bytes
*100
)
```

## 10. Filesystem Usage

```promql
node_filesystem_free_bytes
```

## 11. System Load

```

---

## 12. Boot Time

```

---

## 13. Uptime

## 14. Network Receive

## 15. Network Transmit

## 16. Disk Read Rate

# 1. What is Alerting?

Monitoring tells you what is happening.

Alerting notifies you when something goes wrong.

Instead of checking dashboards all day, Alertmanager sends notifications automatically.

Examples

- CPU Usage > 90%
- Memory Usage > 85%
- Disk Usage > 80%
- Server Down
- Website Down

---

# Why Alerting?

Without Alerts

- Problems remain unnoticed
- Users report issues first
- Longer downtime

With Alerts

- Immediate notification
- Faster issue resolution
- Improved availability

---

# 2. What is Alertmanager?

Alertmanager is a Prometheus component responsible for handling alerts.

It can:

- Receive alerts from Prometheus
- Group alerts
- Remove duplicate alerts
- Send notifications

Supported Notification Channels

- Email
- Slack
- Microsoft Teams
- PagerDuty
- Webhook

# 6. Creating Alert Rules

Create

```bash
sudo nano /etc/prometheus/alert_rules.yml
```

Example

```yaml
groups:

- name: Linux Alerts

  rules:

  - alert: HighCPUUsage

    expr: 100 - (
      avg by(instance)
      (
        rate(node_cpu_seconds_total{mode="idle"}[5m])
      ) *100
    ) > 80

    for: 2m

    labels:
      severity: warning

    annotations:
      summary: CPU Usage is High
      description: CPU usage is above 80%
```

---

Load Rule File

Edit

```yaml
rule_files:
  - "alert_rules.yml"
```

Restart

```bash
sudo systemctl restart prometheus
```
